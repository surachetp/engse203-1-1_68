# วิเคราะห์ Error และการทำงานของ Jest

## วิเคราะห์ Error ในโปรเจค

1. **ประเภทของ Error ที่พบบ่อย**
   - Syntax Error: โค้ดเขียนผิดรูปแบบ
   - Runtime Error: เกิดขึ้นขณะรัน เช่น เรียกใช้ฟังก์ชันที่ไม่มี หรือข้อมูลไม่ตรงกับที่คาด
   - Assertion Error: ผลลัพธ์ไม่ตรงกับที่ test คาดหวัง (expectation ไม่ตรง)
   - Module Not Found: ไม่พบไฟล์หรือโมดูลที่ import
   - Mock/Stub Error: mock ไม่ตรงกับโค้ดจริง หรือไม่ได้ mock module ที่ต้องการ

2. **วิธีวิเคราะห์ Error**
   - อ่านข้อความ error ใน terminal หรือรายงาน coverage
   - ดู stack trace เพื่อหาตำแหน่งที่เกิดปัญหา
   - ตรวจสอบว่า test case, mock, และโค้ดจริงตรงกันหรือไม่
   - ใช้การ debug หรือเพิ่ม console.log เพื่อดูค่าตัวแปรระหว่างรัน

3. **แนวทางแก้ไข**
   - แก้ไขโค้ดหรือ test ให้ตรงกับความคาดหวัง
   - ปรับ mock/stub ให้จำลองพฤติกรรมเหมือน production
   - ตรวจสอบ path/module ที่ import ให้ถูกต้อง
   - รัน test ซ้ำจนกว่าทุก test จะผ่าน

---

## Jest ทำงานอย่างไร

1. **Jest คืออะไร**
   - Jest เป็น JavaScript Testing Framework ที่ใช้สำหรับทดสอบโค้ดทั้ง unit, integration และ snapshot
   - รองรับการ mock module, spy, และตรวจสอบการเรียกใช้งานฟังก์ชัน

2. **กระบวนการทำงานของ Jest**
   - Jest จะค้นหาไฟล์ test (เช่น *.test.js, *.spec.js) ตาม config หรือโฟลเดอร์ที่กำหนด
   - รันแต่ละ test case ในสภาพแวดล้อม isolated (แยกกัน)
   - ใช้ assertion (expect) เพื่อตรวจสอบผลลัพธ์
   - แสดงผลลัพธ์ test ทั้งหมด พร้อมสรุปว่าผ่าน/ไม่ผ่านกี่รายการ
   - สามารถสร้างรายงาน coverage เพื่อดูว่ามีโค้ดส่วนไหนที่ยังไม่ได้ทดสอบ

3. **ฟีเจอร์สำคัญของ Jest**
   - Mocking: สร้าง mock function/module เพื่อควบคุมผลลัพธ์
   - Snapshot Testing: ตรวจสอบ UI หรือ output ที่ต้องการให้เหมือนเดิม
   - Watch Mode: รัน test อัตโนมัติเมื่อไฟล์เปลี่ยนแปลง
   - Code Coverage: รายงานเปอร์เซ็นต์โค้ดที่ถูกทดสอบ

4. **ข้อดีของ Jest**
   - ใช้งานง่าย ไม่ต้อง config เยอะ
   - รันเร็ว รองรับ parallel test
   - มี community และ plugin เยอะ

---

**สรุป:**
การวิเคราะห์ error ช่วยให้แก้ปัญหาได้ตรงจุด ส่วน Jest เป็นเครื่องมือที่ช่วยให้การทดสอบโค้ดเป็นระบบและมีประสิทธิภาพมากขึ้น
